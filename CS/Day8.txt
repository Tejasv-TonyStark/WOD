Operating Systems - Memory Management Interview Report

Q1) Why do we need Memory Management?
Answer:
Memory Management is required to allocate memory to processes, protect processes from accessing each other's memory, deallocate memory after termination, and provide isolation.

Q2) Logical Address vs Physical Address
Logical Address:
- Generated by CPU.
- Seen by the program.
- Belongs to virtual address space.

Physical Address:
- Actual address in RAM.
- Used by memory hardware.

MMU translates logical address into physical address.

Q3) What is MMU?
MMU (Memory Management Unit) is hardware that converts logical addresses generated by CPU into physical addresses using the page table.

Flow:
CPU -> Logical Address -> MMU -> Page Table -> Physical Address -> RAM

Q4) Why not use physical addresses directly?
Because the physical location of a program can change every time it runs. Logical addressing provides protection, flexibility, and supports virtual memory.

Q5) Address Binding
1. Compile-Time Binding:
Address fixed during compilation.

2. Load-Time Binding:
Address fixed when program is loaded into memory.

3. Execution-Time Binding:
Address translation happens during execution using MMU. Modern OS uses this.

Q6) Contiguous Memory Allocation
Each process occupies one continuous block of physical memory.

Advantages:
- Simple
- Fast

Disadvantage:
- Fragmentation

Q7) First Fit, Best Fit, Worst Fit

First Fit:
Allocate the first block large enough.

Best Fit:
Allocate the smallest block that can satisfy the request.

Worst Fit:
Allocate the largest available block.

Q8) Internal Fragmentation
Unused memory inside an allocated block.

Example:
Requested = 100 MB
Allocated = 120 MB
Unused = 20 MB

Q9) External Fragmentation
Free memory exists but is scattered into small blocks, preventing large allocations.

Q10) Compaction
Compaction moves processes together to combine scattered free spaces into one large block.

Solves:
External Fragmentation

Does not solve:
Internal Fragmentation

Q11) Why Paging?
Contiguous allocation requires a process to occupy continuous memory, causing external fragmentation.

Paging divides:
- Logical memory into pages
- Physical memory into frames

Pages are mapped to frames using a page table.

Q12) Address Translation in Paging

Logical Address:
Page Number + Offset

Page Table:
Page Number -> Frame Number

Physical Address:
Frame Number + Offset

Offset remains unchanged because page size and frame size are equal.

Q13) Page Table
Stores mapping between logical pages and physical frames.

Page Table Entry contains:
- Frame number
- Valid bit
- Protection bits
- Dirty bit
- Reference bit

Q14) TLB
Translation Lookaside Buffer is a small cache inside MMU storing recently used page table entries.

TLB Hit:
Entry found in TLB.

TLB Miss:
Entry not found, page table lookup required.

Q15) Virtual Memory
Virtual Memory allows a process to execute even when the complete program is not loaded into RAM by using secondary storage as an extension of memory.

Q16) Virtual Memory vs Demand Paging

Virtual Memory:
Overall concept of using storage with RAM to provide larger memory.

Demand Paging:
Technique where pages are loaded into RAM only when needed.

Q17) Page Fault
Occurs when a process accesses a page that is not currently present in RAM.

Steps:
1. CPU requests page.
2. Page table shows page absent.
3. OS loads page from storage.
4. Page table is updated.

Q18) Why are Page Faults expensive?
Because storage access is much slower than RAM. The OS must load the page, update tables, and resume execution.

Q19) Thrashing
A condition where the OS spends more time handling page faults and swapping pages than executing processes.

Cause:
Too many processes competing for limited memory.

Q20) Page Replacement Algorithms
Used when RAM is full and a new page needs to be loaded.

FIFO:
Removes oldest page.

Optimal:
Removes the page that will not be used for the longest time in future.

LRU:
Removes the page that has not been used for the longest time in the past.

Clock:
Improvement over FIFO using reference bits.

Q21) Optimal vs LRU

Optimal:
- Looks at future.
- Best possible.
- Not practically implementable.

LRU:
- Looks at past usage.
- Practical approximation.
- Used in real systems.
