Day 6Q1)Why do we need a Monitor when we already have Mutex and Semaphore?A Monitor is a high-level synchronization construct that encapsulates shared data and the operations performed on that data while automatically providing mutual exclusion. Unlike semaphores and mutexes where programmers explicitly manage lock and unlock operations, monitors handle synchronization internally, reducing synchronization errors.Note : In the mechansims such as  Mutex or semaphoreIf the programmer makes a mistake:forgets unlock → deadlockwrong semaphore order → deadlockincorrect signaling → starvationQ2)Suppose a thread enters a monitor but the condition it needs is not satisfied.Example:A consumer enters a buffer monitor, but the buffer is empty.Should it:A) Keep running and continuously check?B) Release the monitor and sleep until the condition becomes true?Why?✅ Option B: WaitThe thread:Releases the monitor lock.Goes to sleep.Allows another thread (producer) to enter.Note : Semaphore wait()Means:"Can I acquire this resource?"Condition Variable wait()Means:"The condition I need is not satisfied, so I will sleep until someone changes the state."Q3)Producer adds an item to the empty buffer.It calls:signal()Who should wake up?A) Any random threadB) A thread waiting on that specific conditionWhy?A condition variable wakes up a thread that is waiting for a specific condition. The thread was blocked because the required condition was false, and when another thread changes the state, it signals the condition variable so the waiting thread can continue execution.Q4)Why can't we simply use a normal while loop instead of a condition variable?A normal while loop causes busy waiting, where a thread continuously checks the condition and wastes CPU cycles. A condition variable allows the thread to sleep when the condition is false and wake up only when another thread signals that the condition may have changed.Q5)Differnces between Mutex/Semaphore and a MonitorMutex/Semaphore	MonitorLow-level mechanism	High-level constructProgrammer manages locks	Synchronization managed internallyEasier to misuse	SaferUses wait/signal explicitly	Uses condition variablesQ6)Solution for Dining Philosopher Problem?The deadlock can be prevented by breaking one of the deadlock conditions. Since none of the processes can proceed and release their resources, they remain waiting indefinitely.Q8)What are 4 Conditions of a deadlock?Deadlock needs all four: Mutual exclusion, Hold and wait, No preemption, Circular wait."Q9)Process P1 holds Resource Aand waits for Resource BProcess P2 holds Resource Band waits for Resource A"The scenario clearly shows Hold and Wait and Circular Wait. It shows which resources are allocated to processes and which resources are being requested by processes, helping us identify possible deadlocks.(Before exam in depth on how it works)If every resource has only one instance:Example:Printer → only 1 printerLock → only 1 lockThen:Cycle = DeadlockQ12)Does Cycle always mean a Deadlock in RAG?A cycle in a Resource Allocation Graph indicates deadlock only when each resource type has a single instance. If resource types have multiple instances, a cycle indicates only the possibility of deadlock and further analysis is required.Q13)What is difference bwteen DeadLock avoidance and DeadLock Prevntion?Deadlock prevention eliminates one of the necessary Coffman conditions, making deadlock impossible. Deadlock avoidance allows the conditions to exist but carefully allocates resources only if the system remains in a safe state, commonly using Banker's Algorithm.Q14)If a system is in a safe state is there any possibility of the Deadlock?No, a deadlock cannot occur immediately if the system is in a safe state because a safe state means there exists at least one possible sequence in which all processes can complete without causing deadlock.Q15)What is difference bwteen Safe and Unsafe State?A system is in a safe state if there exists at least one sequence of process execution (safe sequence) where every process can acquire its required resources, complete execution, and release resources without causing deadlock.Q16)About Bankers Algorithm?(DeadLock Avoidance Algorthm)Before giving resources to a process, will the system remain in a safe stateThe banker should not immediately grant the request. Before allocating resources, it should check whether the allocation keeps the system in a safe state. If the system becomes unsafe, the request is denied or the process waits.AvailableResources currently free.AllocationResources already given to processes.MaximumMaximum resources a process may need.NeedRemaining resources required:Need = Maximum - AllocationQ17)Flow of Bankers Algorithm?(Will be checked before the  Interview)Process requests resources          |          ↓Pretend to allocate resources          |          ↓Check if safe sequence exists          |          ↓      Safe?     /     \   Yes      No   |         |Grant     WaitQ18)What is DeadLock detection?Deadlock Detection is a technique where the system allows deadlocks to occur and periodically checks whether a deadlock exists. If detected, recovery methods are applied to resolve it.Q19)How can deadlock be recovered?Deadlock recovery can be done by either terminating one or more deadlocked processes or by preempting resources from processes and reallocating them. Process termination is simpler but may lose computation, while resource preemption preserves processes but is more complex.Q20)What is the difference between Deadlock Avoidance and Deadlock Detection?Deadlock avoidance checks before allocating resources whether the system will remain in a safe state. If granting the request can lead to an unsafe state, the request is delayed.
